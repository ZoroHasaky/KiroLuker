# 浏览器模块

## 使用

1. 打开侧栏「浏览器」，启用自定义 SOCKS5，填写代理主机、端口、用户名和密码。
2. 点击「保存配置」，再点击「测试已保存配置」检查实际出口。未保存修改时不允许测试或启动，避免误用旧配置。
3. 在浏览器页面打开空白窗口或所选账户；账户管理的「前往官网」也会使用这套配置。
4. 每次启动新建临时会话和代理连接，沿用填写的 SOCKS5 用户名，不拼接服务商 Session 参数，也不需要提取 API。
5. 窗口支持地址栏、多个页签、前进/后退、刷新/停止和 Ctrl+L / Ctrl+T / Ctrl+W。

密码通过系统安全存储加密，不回显到页面；密码框留空保留已有密码，使用「清除已保存密码」后保存才会删除。未启用本模块代理时沿用系统网络设置，不借用订阅后台的代理会话。

## 隔离与行为边界

- 每个窗口是独立的非持久化 Electron Session；同窗页签共享登录态与代理，不同窗口不共享。
- 启动检测到与当前窗口或本次应用运行中上次成功启动相同的出口，最多重新连接三次，仍重复则停止启动。
- 出口 IP 是启动时检测样本。是否以及何时轮换由服务商决定，不能据此保证整个窗口生命周期使用同一 IP。
- 代理验证/连接失败不回退直连。窗口关闭会关闭转接连接并清除 Cookie、缓存、站点存储和认证缓存；退出会取消进行中的代理检测。
- 网页视图无账户管理 preload、无 Node 权限、启用沙箱；只允许 HTTP/HTTPS 与空白页，禁用非代理 WebRTC UDP，默认拒绝网站设备权限和下载。
- UA、语言、时区和窗口尺寸是基础配置，不是完整的反关联/匿名方案；没有 Canvas/WebGL/音频等深度指纹伪装。
- 手动新建页签在导航前应用参数。原生网页弹窗优先保留 Chromium 的 opener、POST 和登录链路：首轮页面脚本可能在自定义时区生效前运行，不宣称完整首屏指纹一致性。
- 配置变更仅对之后打开的窗口生效。关窗不保存网页历史、环境档案，也不改变账户的本地订阅标签。

## 本地验证

先生产构建，再运行浏览器回归：

```text
npm run build
npm test
npm run test:browser
npm run test:subscription-ui
```

浏览器测试使用隐藏的真实 Electron 窗口、本机认证 SOCKS5、合成账号及本地 HTTP/HTTPS 站点；不会请求真实代理服务商或操作真实订阅。测试截图和日志位于项目的 out 目录。实际服务商轮换效果与真实官网登录由使用者另行验收。
